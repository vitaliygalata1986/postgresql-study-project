# PostgreSQL

## Локальный запуск

1. Перейдите в `server/` командой `cd server` и запустите `npm ci`.
2. Скопируйте [.env.example](server/.env.example) в `.env` командой `cp -n .env.example .env`. Если у вас уже есть `.env`, отредактируйте его.
3. Укажите в `PGPASSWORD` действующий пароль пользователя PostgreSQL из `PGUSER`. По умолчанию это пользователь `postgres`. Пример рассчитан на базу `node_api` на `localhost:5432`. Если параметры вашей базы отличаются, измените их в `.env`.

   `dotenv` загружает `.env` в `process.env` при запуске приложения. `.env` исключён из Git.

4. Для новой базы создайте таблицу `posts`.

   ```sql
   CREATE TABLE posts (
       id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
       title TEXT NOT NULL,
       anons TEXT,
       full_text TEXT
   );
   ```

5. Из `server/` запустите `npm start` или `npm run dev` для перезапуска при изменении файлов. API доступен на `http://localhost:3000`. При успешном подключении к базе появится сообщение `Connected to PostgreSQL`.

6. Чтобы открыть веб-интерфейс, в другом терминале запустите клиент по [инструкции в client/README.md](client/README.md#локальный-запуск).

## API постов

Полный контракт запросов и ответов описан в [OpenAPI 3.1](server/openapi.json).

| Метод и путь | Результат |
| --- | --- |
| `GET /` | `200` и список постов от новых к старым по `id` |
| `POST /posts/add` | `200` и `Post added successfully` или `400` при некорректном заголовке |
| `PATCH /posts/:id` | `200` и `Post updated successfully` или `400` при некорректном заголовке |
| `DELETE /posts/:id` | `200` и `Post deleted successfully` или `404`, если поста нет |

`POST` и `PATCH` принимают JSON и `application/x-www-form-urlencoded`. При создании `title` обязателен. При обновлении пропущенные поля и поля со значением `null` сохраняют прежние значения. Новый заголовок должен быть строкой с хотя бы одним непробельным символом и сохраняется в исходном виде. Лишние ключи игнорируются.

`PATCH` возвращает `200` и для отсутствующего поста. `id` должен преобразовываться в PostgreSQL `INTEGER`. Ошибки запроса к базе возвращают `500`, а ошибки разбора JSON — `400`.
